Without vs with

Without Sentinel

  • You push C:\Users\alice\... once a month. Nobody else can reproduce. You debug it 2 weeks later.
  • Your agent writes "signature_placeholder": "SIG_RSA_SHA256_...". Ships to main. Your next release claims cryptographic signing.
  • Your MA pipeline returns "unknown_ratio" on a schema mismatch. 465 reviews get corrupted silently.
  • Your AGENTS.md says v2.1.0. Your pyproject.toml says v3.1.0. Drift persists for 7+ days.
  • Rule violations keep happening because advice is advisory.

With Sentinel

  • Pre-push hook BLOCKs the absolute-path commit before it leaves your laptop. ~1.8s.
  • Placeholder HMAC fires [BLOCK] P0-placeholder-hmac. You replace with real TRUTHCERT_HMAC_KEY-derived sig.
  • P1-silent-failure-sentinel catches silent-failure returns. You raise KeyError with the schema diff instead.
  • P2-agent-config-version-drift catches the stale claim at next push. Fix in the same commit.
  • Every rule encodes a real past incident — weakening a rule fails a regression test immediately.

Install in 60 seconds

Works on Windows + Ubuntu, Python 3.11 / 3.12 / 3.13. Zero external runtime dependencies.

# Clone + install
git clone https://github.com/mahmood726-cyber/Sentinel.git
cd Sentinel
pip install -e ".[dev]"

# See the rules
python -m sentinel list-rules

# Try it on an existing repo (no install, just scan)
python -m sentinel scan --repo /path/to/your/repo

# Install the pre-push hook
python -m sentinel install-hook --repo /path/to/your/repo

# Emergency escape valve (logged to ~/.sentinel-logs/bypass.log)
SENTINEL_BYPASS=1 git push

The hook installer also auto-adds STUCK_FAILURES.md / sentinel-findings.md to the target repo's .gitignore — one less footgun.
